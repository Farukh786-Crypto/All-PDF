Json Token .

Header 			. payload  .         signature

Claims - it talks about what roles and rights the user has with respect to the system.

AuthGuard:

@Injectable({
  providedIn: 'root'
})
export class AuthGuard implements CanActivate {

  constructor(
    private authService: AuthService,
    private router: Router
  ) {}

  canActivate(route: ActivatedRouteSnapshot): boolean {
	// get token here
    const token = this.authService.getToken();

    if (!token) {
      this.router.navigate(['/login']);
      return false;
    }
	// hey roles here
    const userRoles = this.authService.getRoles();

    const allowedRoles =
      route.data['roles'] as string[];

    const hasAccess =
      allowedRoles.some(role =>
        userRoles.includes(role)
      );

    if (!hasAccess) {
      this.router.navigate(['/unauthorized']);
      return false;
    }

    return true;
  }
}

The Factory Pattern is a Creational Design Pattern that provides 
an interface for creating objects but allows a dedicated Factory class to decide which concrete class to instantiate at runtime.

step 3> create Factory patteren This class uses IServiceProvider to dynamically pull the right object from the .NET DI container.

// IPaymentGatewayFactory.cs

public interface IPaymentGatewayFactory
{
	IPaymentGateway getPaymentGetway(string gateway);
}

// PaymentGatewayFactory.cs

public class PaymentGatewayFactory : IPaymentGatewayFactory
{
	private readonly IServiceProvider _serviceProvider;
	
	public PaymentGatewayFactory(IServiceProvider serviceProvider)
    {
        _serviceProvider = serviceProvider;
    }
	
	public IPaymentGateway getPaymentGetway(string gatewayType)
	{
		return gatewayType.ToLower() switch
		{
			case "Paypal" => _serviceProvider.GetRequiredService<Paypalgateway>(),
			      
			case "Stripe" => _serviceProvider.GetRequiredService<StripeGateway>(),
			default :
				throw new ArgumentException("Invalid payment gateway type");
		}
	
	}
}

If an interviewer asks: "What problem does the Factory pattern solve?", give them this 3-point answer:

Centralization: "It centralizes object creation logic. If we need to change how a PaymentGateway is created, we only change it in the Factory, not across the entire application."

Abstraction: "It allows the calling code to remain ignorant of concrete implementations. The Controller only works with IPaymentGateway, making the code loosely coupled."

Extensibility: "It makes the code Open for Extension but Closed for Modification. I can add GooglePay, ApplePay, or BitCoin by adding new classes and updating the Factory,
 without ever touching the existing Order or Checkout logic."

																		2. Unit Of Work 
																		

In your microservices project (specifically the Ordering.API which uses SQL Server), you might have multiple repositories—for example, an OrderRepository and a CustomerRepository.

Without Unit of Work, if you update an Order and then update a Customer, you have to call _context.SaveChanges() twice. If the first one succeeds but the second one fails,
 your database is now in a "half-baked" state. This is a disaster for data integrity.
 
 
Quest > What is Unit Of Work
- The Unit of Work is a pattern that groups one or more operations (usually across multiple repositories) into a single transaction. 
It ensures that either all changes are committed to the database, or none of them are.

Quest > What recurring problem it solve
Concurrency: It prevents multiple repositories from opening multiple connections to the same database.


public void ProcessOrder(Order order)
{
    _orderRepo.Add(order);
    _orderRepo.SaveChanges(); // First Hit to DB

    _customerRepo.UpdateLoyaltyPoints(order.CustomerId);
    _customerRepo.SaveChanges(); // Second Hit to DB -> If this fails, the Order above is already saved! (Bad)
}

step 1> The Interface
public interface IUnitOfWork : IDisposable
{
    IOrderRepository Orders { get; }
    ICustomerRepository Customers { get; }
    Task<int> CompleteAsync(); // This is the ONLY place SaveChanges is called
}


step 2>The Implementation


public class UnitOfWork : IUnitOfWork
{
    private readonly OrderContext _context;
    public IOrderRepository Orders { get; private set; }
    public ICustomerRepository Customers { get; private set; }

    public UnitOfWork(OrderContext context)
    {
        _context = context;
        Orders = new OrderRepository(_context);
        Customers = new CustomerRepository(_context);
    }

    public async Task<int> CompleteAsync()
    {
        return await _context.SaveChangesAsync();
    }

    public void Dispose() => _context.Dispose();
}

step 3> Usages in your Ordering.ApiController

public async Task HandleOrder(Order order)
{
    _uow.Orders.Add(order);
    _uow.Customers.UpdateLoyaltyPoints(order.CustomerId);

    // One single transaction!
    await _uow.CompleteAsync(); 
}


Repository Pattern: Handles "How" to get/save data (The logic).

Unit of Work: Handles "When" to save data (The transaction).

to increase api speed
async and await code = perform asynchronous calling using async and await (context switching)


class program
{

	static void Main(string[] args)
	{
		Method(); // call
		Console.WriteLine("Main Method");
		Console.ReadLine();
	}
	
	public static async void Method()
	{
		await Task.Run(new Action(LongTask)); // wait for response until main thread is running
		Console.WriteLine("New Thread");
	}
	public static void LongTask()
	{
		Thread.sleep(20000);
	}

}


What actually happens:

Main thread calls Method()
Main thread hits await → it pauses at that line and says "okay, you go run LongTask, tell me when done"
A background thread is created and runs LongTask() independently (sleeping 20 seconds)
Meanwhile, main thread is free — not frozen, not stuck
When background thread finishes, it sends the response back
Main thread wakes up and continues → prints "New Thread"


The background thread is like a restaurant kitchen — you (main thread) place the order and sit free to do other things. Kitchen (background thread) cooks. 
When food is ready, waiter calls you back. You didn't stand frozen at the counter the whole time.

	{
		var task1 = _httpClient.GetAsync("api1");  // first api
		var task2 = _httpClient.GetAsync("api2");  // second api
		try
		{
			await Task.WhenAll(task1,task2); // if one api failed it throw exception
		}

		{
			Console.WriteLine(ex.Message);
		}
		var response1 = await task1;
		var response2 = await task2;
	}

}

Q>Why use Task.WhenAll?
Answer:
It executes multiple asynchronous operations concurrently, reducing the total execution time compared to awaiting each operation sequentially.

Q>Does Task.WhenAll create new threads?
Answer:
No.It doesn't create new threads. It waits for multiple asynchronous tasks that are already running to complete. The operations are typically I/O-bound,
 so they don't require dedicated threads while waiting.


Q>Why not write this?

await _httpClient.GetAsync("api1");

await _httpClient.GetAsync("api2");

Answer:
Because the second request starts only after the first one completes, increasing the total response time.


Q> When should you use parallel API calls?

Use them when:

APIs are independent.
One API doesn't depend on the result of another.

Examples:

Dashboard data
Product + Category lists
Customer + Orders
Multiple microservice calls

Don't use parallel execution when the second API depends on data returned by the first API.

Why is Repository Scoped?

"Repository depends on DbContext, and DbContext is scoped to a single HTTP request. Using Scoped ensures all repositories in that request share the same DbContext, 
which supports a consistent unit of work and proper transaction handling."


Why is EmailService Transient?
"EmailService is stateless. Each email operation is independent and doesn't need to share data with other operations or requests. 
Creating a new instance each time avoids unnecessary shared state and makes the service naturally thread-safe."


| Lifetime      | Object Created        | Best For                        | Example                                         |
| ------------- | --------------------- | ------------------------------- | ----------------------------------------------- |
| **Singleton** | Once for application  | Shared services                 | `IMemoryCache`, `ILogger`, `IHttpClientFactory` |
| **Scoped**    | Once per HTTP request | Request-specific services       | `DbContext`, Repository, Unit of Work           |
| **Transient** | Every injection       | Lightweight, stateless services | `EmailService`, `PdfGenerator`, `HashService`   |

here it create new runtime column SalaryRank here..

ROW_NUMBER() - Every row gets a unique number.
RANK() - duplicate found then assign same rank and skipped current rank 

DENSE_RANK() - no skipped rank or no gap


| Requirement                                 | Function         |
| ------------------------------------------- | ---------------- |
| Every row unique                            | `ROW_NUMBER()`   |
| Competition ranking                         | `RANK()`         |
| Highest, second highest, nth highest salary | `DENSE_RANK()` ✅ |


Q: Why use DENSE_RANK() instead of ROW_NUMBER()?
"ROW_NUMBER() assigns a unique number to every row, even when salaries are the same. For finding the second highest salary, 
DENSE_RANK() is more appropriate because employees with the same salary receive the same rank, and there are no gaps in the ranking."

Why do we use them?

They are serverless → you don’t manage servers.

They scale automatically → if 100 files are uploaded, Azure spins up more function instances.

They are event-driven → they only run when triggered.

Key Concepts (Beginner Level)
host.json → Settings for how functions behave (timeouts, retries, logging).

local.settings.json → Local development settings (connection strings, secrets).

Scaling → Functions scale based on events (queue length, blob uploads).

Timeouts → Consumption plan has 5 min limit, Premium plan allows longer.

Queue Trigger → Function runs when a message is added to a queue.

Blob Trigger → Function runs when a file is uploaded to Blob Storage.


In our project, we had a challenge where downloading loan documents from ICE Mortgage API took 10–30 minutes, which caused API timeouts. 
We solved this using Azure Functions and Queue-based async processing.
The client sends a request, we immediately return a TaskId, and enqueue the work. A queue-triggered Azure Function picks up the job, 
processes the documents step by step, and updates status in Azure Table Storage. 
The client can poll for status or get notified via webhook. This design avoids timeouts, scales automatically, and keeps the workflow reliable.



Example 1

Interviewer: "Tell me about a real Azure Functions project you've worked on."

Your Answer:
"In Msysuite, when users upload files, we trigger an Azure Function via Blob Trigger. 
The function processes the file — validates type/size, generates thumbnails for images, 
and stores metadata in SQL Server. We used Event Grid-based blob triggers for near-real-time 
processing instead of polling-based classic blob triggers."



Interviewer: "How do you handle file downloads and metadata storage?"

Your Answer:
"When a new file lands in blob storage, our Azure Function triggers, downloads the file 
for processing, extracts metadata (size, extension, MIME type, creation date), and stores 
it in SQL Server via Entity Framework. We use output bindings for SQL to keep the code clean."

public async Task DownloadInChunks(BlobClient blobClient, string localPath)
{
    var properties = await blobClient.GetPropertiesAsync();
    long fileSize = properties.Value.ContentLength;
    long chunkSize = 1 * 1024 * 1024; // 1MB chunks

    using var fileStream = File.OpenWrite(localPath);

    for (long i = 0; i < fileSize; i += chunkSize)
    {
        // Request a specific byte range
        var downloadInfo = await blobClient.DownloadAsync(new HttpRange(i, chunkSize));
        
        await downloadInfo.Value.Content.CopyToAsync(fileStream);
    }
}

bool CheckAnagram(string s, string t)
{
    // 1. Length check
    if (s.Length != t.Length)
    {
        return false;
    }

    // 2. Frequency array for ASCII (0-255)
    int[] ch = new int[256];

    for (int i = 0; i < s.Length; i++)
    {
        ch[s[i]]++;  // count chars in s
        ch[t[i]]--;  // un-count chars in t
    }

    // 3. Check if all counts are zero
    for (int i = 0; i < ch.Length; i++)
    {
        if (ch[i] != 0)
        {
            return false;  // mismatch found
        }
    }

    return true;  // all zero → anagram
}

public bool IsValid(string s) {
    // 1. Create our "Stack" of plates
    Stack<char> myStack = new Stack<char>();

    // 2. Look at every character in the string one by one
    foreach (char c in s) {
        // If it's an opening, push it to the stack
        if (c == '(' || c == '[' || c == '{') {
            myStack.Push(c);
        }
        // If it's a closing, we need to check the top
        else {
            // If we have a closing bracket but the stack is empty, it's wrong!
            if (myStack.Count == 0) return false;

            char top = myStack.Pop(); // Take the top plate off

            // Check if the pair is wrong
            if (c == ')' && top != '(') return false;
            if (c == ']' && top != '[') return false;
            if (c == '}' && top != '{') return false;
        }
    }

    // 3. If the stack is empty, return true. If stuff is left over, return false.
    return myStack.Count == 0;
}

RxJS: shareReplay() — Smart Caching
===================================

shareReplay(bufferSize)
  → Shares one subscription among multiple subscribers
  → Replays last N values to new/late subscribers
  → Prevents duplicate HTTP calls
  → Parameter: how many emissions to remember

shareReplay(1)  = remember last 1 value (most common)
shareReplay(3)  = remember last 3 values
shareReplay()   = remember ALL values (unbounded — use with caution!)

Use Case: API caching in Angular services
  → Employee 1 fetched? Don't fetch again!
  → Multiple components need same data? Share one call!

Important:
  → shareReplay() caches the Observable, not just the data
  → Cache persists for lifetime of the Observable
  → For cache expiration, use custom logic or switchMap with timer
  
  
  
  
RxJS: catchError + retry for Failed API Calls
=============================================

catchError(handler)
  → Catches error in stream
  → Can recover (return fallback) or rethrow
  → Must return new Observable

retry(count)
  → Retries immediately, count times
  → Simple but no delay between retries

retryWhen(errorObservable => logic)
  → Custom retry logic with delays
  → Use delay(), delayWhen(), timer() for spacing
  → Use take(n) to limit retries

Exponential Backoff Pattern:
  → delay = 2^retryCount * 1000ms
  → 1st retry: 2s, 2nd: 4s, 3rd: 8s...
  → Prevents overwhelming server

Best Practice:
  1. retryWhen with delay for transient errors
  2. catchError to transform error for UI
  3. shareReplay to avoid duplicate retries
  4. Component shows loading + error states




import { retryWhen, delay, take, catchError } from 'rxjs/operators';
import { timer } from 'rxjs';

getUserById(id: number) {
  return this.http.get(`https://jsonplaceholder.typicode.com/users/${id}`)
    .pipe(
      retryWhen(errors => 
        errors.pipe(
          delay(2000),     // ← Wait 2 seconds between retries
          take(3)          // ← Retry max 3 times
        )
      ),
      catchError(error => {
        return throwError(() => new Error('Service unavailable after retries'));
      })
    );
}

// 1. $users and $posts are declared as const inside constructor (not accessible outside)
// 2. forkJoin references this.$users and this.$posts (undefined!)
// 3. No type safety
// 4. Subscribing to same observables multiple times = multiple HTTP calls!


export class MyComponent {
  
  private http = inject(HttpClient);  // Modern Angular inject()

  // Define as class properties
  $users = this.http.get('https://jsonplaceholder.typicode.com/users');
  $posts = this.http.get('https://jsonplaceholder.typicode.com/posts');

  constructor() {
    // forkJoin waits for ALL to complete, then emits combined result
    forkJoin([this.$users, this.$posts]).subscribe({
      next: ([users, posts]) => {
        console.log('Users:', users);   // Array of users
        console.log('Posts:', posts);   // Array of posts
      },
      error: (err) => console.error('Error:', err)
    });
  }
}


| Feature              | Description                            |
| -------------------- | -------------------------------------- |
| **Waits for ALL**    | Waits until every Observable completes |
| **Emits ONCE**       | Emits combined result as an array      |
| **Order preserved**  | Results in same order as input array   |
| **Fails fast**       | If ANY fails, entire forkJoin fails    |
| **Last values only** | Takes only last emission from each     |

@Injectable()
export class UserEffects {
  
  constructor(
    private actions$: Actions,
    private userService: UserService
  ) {}

  // ✅ Effect: Load User
  loadUser$ = createEffect(() => 
    this.actions$.pipe(
      ofType(UserActions.loadUser),           // Listen for "loadUser" action
      switchMap((action) =>                   // Cancel previous, switch to new
        this.userService.getUserById(action.id).pipe(
          map(user => UserActions.loadUserSuccess({ user })),   // Success action
          catchError(error => of(UserActions.loadUserFailure({ error }))) // Error action
        )
      )
    )
  );
}

how to prevent memeory leaks in angular


Angular: Preventing Memory Leaks
=================================

Problem:
  → Subscriptions stay alive after component destroyed
  → Causes memory leaks, unexpected callbacks

Solutions:

1. Subscription Array (Manual)
   private subs: Subscription[] = [];
   this.subs.push(observable.subscribe(...));
   ngOnDestroy() { this.subs.forEach(s => s.unsubscribe()); }

2. takeUntilDestroyed() [Angular 16+]
   .pipe(takeUntilDestroyed())
   → Auto-unsubscribe when component destroyed
   → Only works in injection context

3. async Pipe (Recommended)
   data$ = http.get(...);
   template: {{ data$ | async }}
   → Angular handles subscribe/unsubscribe

4. takeUntil + Subject
   private destroy$ = new Subject<void>();
   .pipe(takeUntil(this.destroy$))
   ngOnDestroy() { this.destroy$.next(); this.destroy$.complete(); }

Best Practice:
  → Use async pipe for template data
  → Use takeUntilDestroyed() for component logic
  → Avoid manual subscription arrays when possible



| Method                     | Code                          | Auto-Cleanup | Best For                 |
| -------------------------- | ----------------------------- | ------------ | ------------------------ |
| **Subscription Array**     | `sub.push()` + `ngOnDestroy`  | ❌ Manual     | Simple components        |
| **`takeUntilDestroyed()`** | `.pipe(takeUntilDestroyed())` | ✅ Auto       | Modern Angular (v16+)    |
| **`async` pipe**           | `{{ data$ \| async }}`        | ✅ Auto       | Template-bound data      |
| **`takeUntil` + Subject**  | `.pipe(takeUntil(destroy$))`  | ⚠️ Manual    | Complex logic, re-usable |


Method 1:(subscription Array)

import { Component, OnDestroy } from '@angular/core';
import { Subscription } from 'rxjs';

@Component({...})
export class EmployeeComponent implements OnDestroy {
  
  private subscriptions: Subscription[] = [];

  getEmployees() {
    const sub1 = this.http.get('/api/employees').subscribe(res => {
      console.log(res);
    });
    this.subscriptions.push(sub1);
    
    const sub2 = this.someService.data$.subscribe(data => {
      console.log(data);
    });
    this.subscriptions.push(sub2);
  }

  ngOnDestroy() {
    this.subscriptions.forEach(sub => sub.unsubscribe());
  }
}


Method 2 : TakeUntilDestroy()


import { Component, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';
import { SomeService } from './some.service';

@Component({
  selector: 'app-employee',
  template: `...`,
  standalone: true
})
export class EmployeeComponent {
  private http = inject(HttpClient);
  private someService = inject(SomeService);

  constructor() {
    this.getEmployees();
  }

  getEmployees() {
    // HTTP call - auto-completes on destroy
    this.http.get('/api/employees')
      .pipe(takeUntilDestroyed())
      .subscribe(res => {
        console.log(res);
      });

    // Long-lived observable - auto-completes on destroy
    this.someService.data$
      .pipe(takeUntilDestroyed())
      .subscribe(data => {
        console.log(data);
      });
  }
}



Method 3 : async pipe (template)


import { Component, inject } from '@angular/core';
import { Observable } from 'rxjs';

@Component({
  template: `
    <div *ngIf="employees$ | async as employees">
      <div *ngFor="let emp of employees">{{ emp.name }}</div>
    </div>
  `
})
export class EmployeeComponent {
  
  private http = inject(HttpClient);
  
  // ✅ Observable exposed to template
  employees$: Observable<any[]> = this.http.get<any[]>('/api/employees');
}

Question 1: What is Change Detection in Angular?
Change Detection is the mechanism Angular uses to detect changes in component data and automatically update the DOM.
 Whenever component properties change, Angular checks the bindings and refreshes the UI.
 
 
Question 2: What is the default Change Detection Strategy?
ChangeDetectionStrategy.Default

Angular checks the component whenever:

Button click
HTTP response
Promise
Observable
Timer
User input



Question 3: What is OnPush?
@Component({
  changeDetection: ChangeDetectionStrategy.OnPush
})
OnPush tells Angular to skip unnecessary change detection and only check the component when specific events occur, improving application performance.


Question 4: Why do we use OnPush?
Improves performance
Reduces unnecessary change detection
Best for large applications
Works well with immutable data

Question 10: Difference between Default and OnPush

| Default                    | OnPush                                      |
| -------------------------- | ------------------------------------------- |
| Checks frequently          | Checks only when triggered                  |
| Easier to use              | Better performance                          |
| Detects property mutations | Requires new references for `@Input` values |
| Suitable for small apps    | Suitable for large apps                     |


Question 17: Can we manually trigger change detection?
constructor(private cd: ChangeDetectorRef) {}
or 
this.cd.detectChanges();



Question 18: What is the difference between markForCheck() and detectChanges()?

markForCheck()

Marks the component to be checked in the next change detection cycle.

detectChanges()

Runs change detection immediately for the component and its children.

															** Angular Custom directives ***
															
A custom directive allows you to add custom behavior to existing HTML elements without modifying the element itself.
<input type="text" appNumberOnly>

Interview Question: Why did you create a custom directive?

In my project, I had multiple forms containing fields such as:

Pin Code
Phone Number
Employee ID
Customer ID

All these fields should accept only numeric values.

Instead of writing the same validation logic repeatedly in every component, I created a reusable custom directive.

Benefits:

Code reusability
Centralized logic
Easier maintenance
Cleaner HTML and TypeScript code
Consistent behavior across the application


Interview Question: Why not use Validators?
Answer

Validators validate data after it is entered.

Example:
Validators.pattern('^[0-9]*$')
User can still type:
abc123
and then Angular shows a validation error.

My directive prevents invalid input from being entered or paste in the first place.
So:
Directive = Prevention
Validator = Validation

In enterprise applications we often use both together.

import { Directive, HostListener } from '@angular/core';

@Directive({
  selector: '[appNumberOnly]'
})
export class NumberOnly {

  @HostListener('keydown', ['$event'])
  onKeyDown(event: KeyboardEvent) {
    const allowedKeys = ['Backspace', 'Tab', 'ArrowLeft', 'ArrowRight', 'Delete'];

    if ((event.key >= '0' && event.key <= '9') || allowedKeys.includes(event.key)) {
      return;
    }

    event.preventDefault();
  }

}

Interview Question: How did you implement it?
Answer

I used Angular's @Directive decorator and @HostListener.
@Directive({
  selector: '[appNumberOnly]'
})
This allows usage like:
<input appNumberOnly>
Then I listened to keyboard events:
@HostListener('keydown', ['$event'])
to block non-numeric keys.
And:
to block non-numeric keys.
@HostListener('paste', ['$event'])


Interview Question: Why HostListener?
Answer

HostListener allows a directive to listen to DOM events occurring on its host element.

Example:
@HostListener('click')
@HostListener('keydown')
@HostListener('paste')
Without manually attaching event listeners.

Interview Question: Where have you used custom directives?

You can answer:

I have used custom directives for:

Number-only input
Uppercase conversion
Auto focus
Disable double click
Role-based element visibility
Highlight invalid controls
Restrict special characters
Trim whitespace automatically


Interview Question: Can you show another example?
Uppercase Directive
@Directive({
  selector: '[appUppercase]'
})
@HostListener('input', ['$event'])
onInput(event: Event) {
  const input = event.target as HTMLInputElement;
  input.value = input.value.toUpperCase();
}
Usage:
